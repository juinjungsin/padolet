# padolet — 교육용 실시간 커뮤니케이션 보드

운영: https://padolet.vercel.app · Next.js 16 + Firebase(Firestore·Auth·Storage, 프로젝트 `jblet-3e6c3`) · Vercel 배포

작업 이력과 결정 사항은 [`taskslog.md`](taskslog.md)에 Phase별로 기록합니다.

## 화면 구성

| 사용자 | 화면 | 주요 기능 |
|---|---|---|
| 교육생 | `/join` → `/board/{id}` | 현재 실습 안내(진행 중·실습 완료·도움 필요·질문하기), 보드/자료/질문/제출 보기, 대화, 투표 |
| 강사 (세션 소유자) | 보드 + `강사 도구` 메뉴 | 진행 요약(도움 요청·미답변 질문·완료 인원), 실습 안내 편집, 질문 상태 변경, 제출 현황·피드백, 타이머·프로젝터·보고서·모더레이션·잠금 |
| 강사 | `/board/{id}/instructor` (새 창) | 강사 진행 화면 — 도움 요청·미답변 질문·실습 진행·제출 현황을 한 화면에 |
| 관리자 | `/admin` | 세션 검색·상태 필터·정렬, 교육일, 보드 열기·보고서, 더보기(QR·정보 수정·템플릿으로 복제·종료·보관·삭제) |
| 최고 관리자 | `/admin/settings` | 관리자 권한 관리 |

## 강사 운영 방법 (요약)

1. **실습 안내** — 보드 상단 `실습 안내 만들기/편집`에서 모듈명·실습 제목·설명·자료 링크·보드 자료·마감·제출 링크를 입력하고 `현재 실습으로 지정`. 교육생 화면 맨 위에 바로 고정됩니다.
2. **진행 확인** — 보드 상단 `진행 요약`의 완료·진행 중·응답 없음, 도움 요청 수를 확인하고 눌러서 요청자별 `확인`·`처리 완료`. 처리 완료는 교육생의 실습 완료 여부를 바꾸지 않습니다.
3. **질문** — `질문` 탭(미답변 수 배지)에서 상태를 접수→답변 중→해결로 바꾸고, 해결한 질문은 다시 접수로 열 수 있습니다. 답변은 댓글로 답니다. 대화 메시지는 메시지 메뉴(⋯)의 `질문으로 등록`으로 옮길 수 있습니다(원본 유지).
4. **자료** — 유형을 `자료`·`프롬프트`로 올리면 `자료` 탭에 모입니다. 공지는 강사만 올릴 수 있습니다.
5. **제출함** — 실습 안내 편집에서 `앱 안 제출함 열기`를 켜면 `제출` 탭이 생깁니다. 교육생은 글·파일(최대 5개)을 제출하고 다시 제출할 수 있으며, 제출한 교육생끼리는 최신 제출물만 서로 봅니다. 제출 이력과 피드백은 본인과 강사만 봅니다. 강사는 `제출` 탭에서 실습별 제출·재제출·미제출 수를 보고 `보기·피드백`으로 피드백을 남깁니다(다시 제출하면 피드백 대기로 돌아감).
6. **강사 진행 화면** — `강사 도구 > 강사 진행 화면 (새 창)`. 보조 모니터에 띄워 두고 도움 요청·미답변 질문·진행·제출 현황을 한 번에 봅니다. 집계는 교육생만 대상입니다(강사·관리자 계정 제외).
7. **프로젝터 크게 보기** — 게시물 메뉴(⋯)나 제출 현황의 `프로젝터에 크게 보기`. 작성자 이름은 기본으로 숨기고, 보드 상단 제어 줄의 `이름 표시`를 눌렀을 때만 보입니다. 제출물은 글·파일명·회차만 띄우고 피드백·이력은 띄우지 않습니다.
8. **템플릿으로 복제** — `/admin` 더보기 > `템플릿으로 복제`. 실습 안내와 강사가 올린 자료·프롬프트·공지만 새 세션으로 옮기고, 교육생 글·질문·대화·제출물·참여자·투표는 복사하지 않습니다. 마감 시각은 비워 둡니다.
9. **보고서** — `강사 도구 > 보고서`. 외부에 공유할 때는 `참여자 명단`·`첨부 다운로드 링크`를 끄고 내보내세요(링크는 주소를 아는 누구나 열 수 있음).

지표 기준: **누적 입장** = 세션에 입장한 브라우저 수(강사 포함, 같은 브라우저 재입장은 1명). **최근 활동** = 약 3분 안에 보드를 띄워 둔 인원. 교육생 식별은 브라우저 익명 계정이라 다른 기기·시크릿 창은 새 참여자로 집계됩니다(제출도 같은 브라우저로 해야 이전 제출과 이어짐).

## 로컬 검증 (운영 Firebase에 접속하지 않음)

필요: Node 20.9+, Java 21 (`JAVA_HOME` 또는 `~/tools/jdk-*`를 자동으로 찾음)

```bash
npm run emulators        # Auth·Firestore·Storage 에뮬레이터 (demo-padolet)
npm run seed             # 가상 데이터 — 세션 코드 TEST / EMPT / ENDD
npm run dev:emulator     # http://localhost:3100 (관리자 로그인 화면에 '에뮬레이터로 로그인')
```

```bash
npm test                 # 단위 테스트 (Vitest)
npm run test:rules       # 보안 규칙 테스트 (에뮬레이터 자동 기동)
npm run test:e2e         # E2E (Playwright — 에뮬레이터·개발 서버 자동 기동)
```

`PADOLET_EMULATOR_OFFSET=1000`처럼 지정하면 모든 포트를 옮겨 두 벌을 동시에 띄울 수 있습니다.
에뮬레이터 로그인은 `NEXT_PUBLIC_USE_EMULATOR=1` + 개발 서버에서만 등록되며 운영 빌드에는 없습니다.

## 보드 편집·칸반·흐름도 (2026-11)

- 포스트잇 메뉴 → **제목·색상·위치 변경**에서 제목, 색상, 배치 번호, 칸반 상태를 저장합니다. 작성자와 보드 관리자가 사용할 수 있으며 설정 변경에는 5분 제한이 없습니다. 본문 수정의 기존 시간 제한은 유지합니다.
- **배치순**에서 이동 손잡이를 다른 카드 위로 끌면 그 카드 앞으로 이동합니다. 모바일·키보드에서는 설정의 배치 번호를 사용합니다. 작은 번호부터 보이며 고정 글은 항상 먼저 나옵니다.
- 보드와 대화 사이 경계선을 끌거나 초점을 둔 뒤 좌우 방향키로 너비를 조절합니다. 브라우저에 너비를 기억하며, 두 번 클릭하면 초기화합니다. 모바일은 기존 보드/대화 탭을 사용합니다.
- **보드 제목 변경**은 등록된 관리자 중 해당 보드 소유자 또는 최고관리자만 가능합니다.
- 대화는 본인 또는 보드 관리자가 확인 후 삭제할 수 있습니다. 연결된 질문으로 이미 복사한 내용과 첨부 파일 자체는 삭제되지 않습니다.
- 포스트잇: 배치순·오래된순·최신순·제목/내용순·작성자순·공감순. 대화: 오래된순·최신순·작성자순·내용순. 대화 정렬은 현재 불러온 메시지에 적용되며 ‘이전 메시지 보기’로 범위를 넓힙니다.
- **칸반**은 기존 포스트잇을 할 일·진행 중·완료로 나눕니다. 열 간 끌기 또는 상태 선택으로 이동하고 새로고침해도 상태를 유지합니다.
- **흐름도**는 참여자별로 하나씩 생성하며 모두가 열람합니다. 작업·분기·시작/종료 버튼 또는 빈 공간 더블클릭으로 객체를 만듭니다. **출발 객체를 선택한 뒤 다른 객체를 우클릭하면 연결**됩니다. 모바일·키보드는 ‘선택 객체에서 연결’ 후 도착 객체를 탭하거나 Enter로 선택합니다. Shift+F10도 우클릭 연결과 같습니다. 연결선 설명은 연결 전에 입력하고, 목록에서 삭제할 수 있습니다.
- **새 창에서 크게 편집**은 현재 초안과 선택 상태를 이어받습니다. 빈 곳 끌기로 화면을 이동하고 휠·두 손가락·+/−로 확대·축소합니다. 고정된 캔버스 경계와 확대율 상하한을 두지 않으며 ‘전체 보기’로 그림 전체를 찾습니다. 새 창을 닫으면 초안은 보드로 돌아옵니다. 원래 보드 창은 열어 둡니다. 팝업이 차단되면 브라우저에서 허용해야 합니다.
- **PNG 저장 / JPG 저장**은 확대율과 관계없이 전체 흐름도를 흰 배경 이미지로 내보냅니다. 브라우저 메모리를 고려해 최대 한 변 8192px·총 1600만 픽셀로 축소하며 이미지에는 표시되는 객체 이름·연결 설명을 담습니다. 긴 객체 이름은 화면과 동일하게 줄임 표시합니다.
- **포스트잇으로 공유 / 대화로 공유**는 미리보기 확인 후 PNG 이미지 사본을 게시합니다. 현재 초안도 공유할 수 있지만 이후 편집은 게시된 이미지에 자동 반영되지 않습니다. 공유에는 기존 잠금·차단·금칙어 설정이 적용됩니다. 작성자와 보드 관리자가 편집한 뒤 **흐름도 저장**을 누르면 원본을 저장합니다. 동시에 수정하면 저장 충돌을 알리고 초안을 보존합니다. 최대 100개 단계·200개 연결선입니다.
- 잠금 중에는 참여자의 포스트잇 설정·칸반 이동·대화 삭제·흐름도 저장이 차단됩니다.
- 새 Firestore 규칙과 앱을 함께 배포해야 합니다. 기존 데이터는 칸반 ‘할 일’로 표시되며 일괄 변환은 필요하지 않습니다. 세션 삭제 시 흐름도도 정리합니다.

## 업무 리디자인 구성도

보드의 **흐름도** 탭에서 `내 업무 템플릿` 또는 `조직 협업 템플릿`으로 시작합니다. 기존 구성도가 있으면 교체 확인을 받으며, 저장 전에는 `최신본 다시 열기`로 저장본을 복구할 수 있습니다.

1. 객체 선택 → **업무 상세**에서 담당 조직·역할, 입력/시작 조건, 산출물, 사용 시스템, 작업/대기 시간을 기록합니다. 현재 문제점과 개선 방향(유지·단순화·자동화·이관/협업·제거), 개선 후 업무안을 함께 남깁니다.
2. **조직별 자동 배치**로 조직별 구획과 연결 순서를 정리합니다. 조직명을 바꾸면 재배치하며, 직접 위치를 옮기려면 **자유 배치로 전환**합니다. 피드백 연결은 점선으로 표시합니다.
3. 기존 우클릭 연결 또는 탭 연결을 이용합니다. **연결선 목록·목록으로 연결**에서 요청·전달·승인·피드백 유형과 전달 산출물, 인수/완료 조건을 편집합니다.
4. **업무 진단**을 펼쳐 미지정 담당자·산출물, 작업보다 긴 대기, 조직 간 전달 산출물 누락을 확인합니다. 시간은 입력된 단계의 단순 합계로, 병렬·반복을 고려한 전체 처리 시간이 아닙니다.
5. **흐름도 저장**으로 원본을 저장합니다. PNG/JPG와 보드 공유에는 조직 구획·담당 조직/역할·개선 방향·협업 유형이 표시됩니다. **업무 진단서 저장**은 상세 입력과 개선안·협업 조건 전체를 Markdown으로 내보냅니다.

기존 구성도도 그대로 열립니다. 기존 작성자/관리자 편집 권한, 보드 잠금, 동시 저장 충돌 검사를 유지합니다.

### Markdown에서 AI로 구성도 생성

**흐름도 → MD 파일에서 AI로 흐름도 만들기**를 펼칩니다.

1. 본인의 **OpenAI API 키**와 모델 ID를 입력합니다. 기본 모델은 `gpt-4o-mini`이며 Responses API의 Structured Outputs 지원 모델을 사용합니다.
2. 업무 설명이 담긴 UTF-8 `.md` / `.markdown` 파일을 선택합니다 (최대 128KB, 60,000자). 파일 선택만으로 AI 요청은 발생하지 않습니다.
3. **AI로 생성**을 누릅니다. 문서 내용은 padolet 서버를 거쳐 OpenAI에 전송되며 해당 API 키의 사용 요금이 적용됩니다. 문서에 명시된 단계·조직·역할·입출력·시스템·협업 관계를 추출하고, 불명확한 내용은 확인 사항으로 표시합니다.
4. 미리보기에서 객체를 선택해 업무 상세를 확인합니다. **현재 흐름도에 적용**을 누르면 기존 초안이 있을 경우 교체 확인 후 적용합니다. 원본 저장은 **흐름도 저장**으로 완료합니다. 적용한 구성도는 직접 편집하고 PNG/JPG 및 보드 공유에 사용할 수 있습니다.

API 키는 화면 메모리에만 유지하며 localStorage/sessionStorage/Firestore/환경 파일에 저장하지 않습니다. 원본 Markdown 파일도 업로드 저장소에 보관하지 않습니다. 서버는 키를 OpenAI의 고정 HTTPS 주소로만 전달하고 `store: false`를 사용합니다. 새로고침하거나 화면을 떠나면 키를 다시 입력합니다. 공용 API 키를 별도로 배포할 필요가 없습니다.

취소·API 한도/키 오류·시간 초과·잘못된 결과는 기존 구성도를 변경하지 않습니다. 생성 취소는 이미 처리된 API 사용량의 청구를 취소하지 않습니다. 서버에서 Firebase 인증·보드 참여 권한·잠금을 검사하며, AI 결과의 단계/연결 수·참조·유형·문자열·시간 값을 검증합니다.

검증은 테스트용 AI 응답과 로컬 Firebase 에뮬레이터로 수행합니다. 실제 유료 AI 호출은 사용자가 직접 입력한 키로 실행합니다.

구현 참고: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Firebase Auth REST 계정 확인](https://firebase.google.com/docs/reference/rest/auth#section-get-account-info).

## 운영 배포 순서
